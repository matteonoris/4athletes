# Apple Health import audit — 2026-09-14

## Units and daily aggregation

`DailyHealthMetricNormalizer` is the single conversion boundary for imported
daily health samples. Conversion happens before averaging and persistence, so
athlete cards, coach reports, charts and recovery inputs share the same values.

| Stream | Stored unit / behavior |
| --- | --- |
| Blood oxygen | Percentage points: Apple `0.97` becomes `97`; Android `97` stays `97` |
| Resting heart rate | Beats per minute |
| HRV | Milliseconds; Apple SDNN and Android RMSSD remain separate series |
| Respiratory rate | Breaths per minute |
| Weight | Kilograms; explicit alternate mass units are converted |
| Apple sleeping wrist temperature | Absolute degrees Celsius, assigned to the local wake date |
| Android skin temperature | Celsius difference from baseline; negative and zero differences remain valid |

Apple defines `HKUnit.percent()` as a fraction from 0 to 1. The pinned health
plugin returns that quantity without multiplying it by 100. The source platform
therefore determines the oxygen conversion; a low Android value is never
silently multiplied. Nonfinite values, incompatible units and oxygen values
outside the provider's range are omitted, rather than inserted as placeholders.

Daily queries begin at local midnight on the first requested day. HRV uses the
existing nighttime policy, now precisely `00:00 <= sample time < 08:00`. Exact
repeated native records are ignored; distinct observations remain distinct.
Sleep duration/stage aggregation continues to union overlapping intervals and
assign overnight sleep to its wake date.

## Historical correction

The health score cache prefix is advanced to `health_sync_v13_health_units_`.
Old cached fractional oxygen values cannot override newly imported percentages.
The existing daily synchronization continues to upsert corrected aggregates.

On iOS, stored oxygen values in `(0, 1]` trigger a HealthKit re-read starting at
the oldest suspect date, including dates older than the regular 90-day window.
Only the oxygen query expands. Stored records lack provider/unit metadata, so
they are not blindly multiplied. Repair requires the corresponding samples to
remain available in Apple Health and permission to read them. Unavailable
historical samples cannot be reconstructed by this change.

## Workout import

The native fallback for workouts without a total distance now reads the sport's
quantity: walking/running, cycling, or swimming. It no longer substitutes
walking/running distance for unrelated sports. Read authorization includes
cycling and swimming, and the Dart fallback includes swimming. The workout
import version advances to 7. Existing official workout totals, energy in kcal,
distance in meters, speed conversion to km/h, and RR/HRV in milliseconds remain
the basis for the import.

## Dependencies and validation

`health` is updated from 13.3.1 to 13.3.2. Its transitive dependencies require
`share_plus` 13.x, updated to 13.3.0. The iOS minimum is aligned to 15.0 in both
the Podfile and Xcode project. On macOS, run `flutter pub get` and `pod install`
before building; the CocoaPods lockfile must be regenerated by CocoaPods.

Dart regression coverage includes percentage conversion, Android compatibility,
persisted/chart values, unit conversion, local dates, HRV time boundaries,
temperature semantics, duplicates, historical repair selection and old-cache
invalidation. Existing sleep, recovery, workout and light/dark display tests
also run. `RunnerTests` covers the native sport-to-distance mapping; executing
it and validating actual HealthKit permissions/samples requires Xcode and an
iPhone/Apple Watch and cannot be done on the Windows development host.

Validation on 2026-09-15: all 73 targeted Flutter tests passed. Static analysis
found no errors in the importer and its regression tests. The Android debug APK
was successfully generated in an isolated build copy at 07:59; its manifest,
DEX, Flutter engine and Dart kernel entries were verified. The importer source
files and dependency manifests match the workspace by SHA-256. The isolated
build avoided temporary shader output conflicts in the shared build directory.
